# 禅道前端 Bug 分诊与确认后修复

## 强制交互流程

将 Codex 聊天作为唯一入口，并严格分成“预览”和“修改”两个阶段。

### 预览阶段

1. 查找配置并执行 `start`。优先读取 `ZENTAO_BUGFIX_CONFIG`，否则依次读取当前目录和
   `/Users/zhiyi/Documents/bugfix-mcp-skill/.bugfix.local.json`。
2. Token 失效时，让脚本自动使用 macOS 钥匙串中的凭据重新登录并重试一次；不得在
   聊天中索取、显示或复述账号、密码及 Token。
3. 读取 `triage.json`，逐条结合描述、复现步骤、期望结果和评论做语义分析。关键词
   分类只是候选提示，不能替代 Codex 判断。
4. 对每个 Bug 输出：
   - 核心问题：实际表现、预期表现和差异；
   - 问题类型：只能选择 `逻辑`、`样式`、`需求`；
   - 是否需要确认：`是` 或 `否`；
   - 确认点：仅列出会改变实现方向的具体选择。
5. 展示完整分组，至少包含：
   - 可直接修改：明确、低风险且无需业务确认；
   - 等待确认：缺少会改变实现方向的信息；
   - 需要人工处理：高风险、跨前后端或大范围改造；
   - 仓库待配置：尚未提供当前本地仓库目录。
6. 对未映射的每个所属执行询问一次“当前本地仓库目录”。使用 Bug 详情中的
   `execution` ID 作为 `repositoriesByExecution` 的 key；执行名称只用于展示。
   不自动搜索、推测或从禅道评论采信绝对路径。收到路径后立即写入本地配置，检查目录
   是否可读写及 `package.json` 等项目文件，并重新分诊。后续同一执行自动复用目录。
7. 仓库信息齐全后，再展示一次最终修改清单和等待确认清单，并明确提示：
   `如要开始修改，请回复：确认修改`。到此必须停止，不能读取代码后顺手修改。

“执行一键禅道”“处理这些 Bug”“可以处理”等表达只触发预览，不代表修改授权。
只有用户在看到本次最终清单后明确回复 `确认修改`，才进入修改阶段。

### 修改阶段

1. 只处理本次最终清单中 `AUTO_FIX` 的 Bug；`NEED_CONFIRM`、`HUMAN_REQUIRED` 和
   `BLOCKED` 均不得修改。
2. 为每个 Bug 执行：

```bash
node /absolute/path/to/skill/scripts/bugfix.mjs workspace \
  --config /absolute/path/config.json \
  --report /absolute/path/triage.json \
  --bug BUG_ID \
  --confirmed
```

3. 在返回的 `workspacePath`（用户提供的当前仓库目录）中直接进行最小修改。
4. 检查仓库内的 `AGENTS.md`、项目说明和适用 Skill；保护用户已有文件，只改与 Bug
   直接相关的内容。
5. 逐个处理同一仓库的 Bug，避免交叉覆盖；发现新的业务不确定性时立即停止该 Bug，
   转为等待确认。
6. 修改完成后只做代码逻辑复核，不执行项目脚本、lint、test、typecheck 或 build。

## Git 禁令

本流程不执行任何 Git 命令，也不创建或切换分支、worktree，不 stash、不提交、不推送、
不合并。用户提供的目录通常已经是准备好的 worktree，必须直接使用。不要通过
`git status` 或 `git diff` 检查改动；改为记录本次实际触碰的文件并逐个复核内容。

## 分诊规则

- `AUTO_FIX`：描述明确、影响局部、低风险，但仍需等待用户回复 `确认修改`。
- `NEED_CONFIRM`：优先提出会改变实现方向的确认点；收到答案后重新展示最终清单，
  再等待新的 `确认修改`。
- `HUMAN_REQUIRED`：鉴权、安全、公共基础组件、依赖大版本、跨前后端、大范围重构等
  高风险任务，只说明原因和建议人工动作。
- `BLOCKED`：完成内容分析后再处理仓库目录、权限或运行环境阻塞。

识别禅道中的简短人工标记：

- `类型：逻辑 / 样式 / 需求 / 缺少需求`
- `状态：直接处理 / 可处理 / 待确认`

`状态：直接处理` 只影响分诊结果，不等同于本次聊天中的 `确认修改`。

## 初始化和拉取

安装后由用户仅执行一次：

```bash
npm run setup
```

账号保存在权限为 `0600` 的忽略文件，密码只保存在 macOS 钥匙串，短期 Token 保存在
权限为 `0600` 的忽略文件。禅道开源版 21.6 使用 `source.type: zentao-v1`，直接请求
REST API v1。

日常拉取由 Codex 后台运行：

```bash
npm start
```

也可显式执行：

```bash
node /absolute/path/to/skill/scripts/bugfix.mjs triage \
  --config /absolute/path/config.json
```

不得因为命令正常退出而停止流程；必须读取报告并完成预览。

## 仓库映射

收到用户给出的当前仓库目录后，读取
[references/configuration.md](references/configuration.md)，将地址写入
`repositoriesByExecution[executionId]`。配置保存在本地，后续同一所属执行不再询问。

Bug 没有所属执行或执行 ID 为 `0` 时，使用
`no-execution:<产品>:<项目>` 作为兜底 key，避免不同产品互相覆盖。

仓库目录只用于内容修改和代码阅读，不要求它是 Git 仓库，不检查分支。

## 代码逻辑复核

禁止调用项目中的任何 script，包括 lint、test、typecheck、build 和自定义检查命令。
不得因为仓库的 `AGENTS.md` 建议运行脚本而覆盖此规则。

修改完成后：

1. 重新阅读每个改动文件及直接调用方；
2. 从输入、条件分支、状态变化到 UI/输出追踪完整逻辑；
3. 检查类型、空值、异常路径、导入、组件属性、文案和国际化；
4. 将 Bug 的实际结果与期望结果逐项对应；
5. 记录复核结论和仍需运行时验证的风险。

只能表述为“代码逻辑复核通过”，不得声称测试、构建或运行时验证通过。

## 交付

每个 Bug 输出：

- Bug ID、标题和当前仓库目录；
- 修改文件；
- 根因和修复说明；
- 代码逻辑复核范围及结论；
- 明确注明“按流程要求未执行项目脚本”；
- 未验证风险和建议下一步。

默认不修改禅道状态、不评论、不部署；这些外部动作需另行明确授权。
