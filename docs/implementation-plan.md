# 禅道前端 Bug 自动分诊与修复：Plugin + MCP 实现方案

## 1. 目标

建立一条可重复执行的本地流水线：

1. 一次拉取禅道中指派给当前用户、尚未关闭的 Bug。
2. 将不同产品、项目和模块的 Bug 归一化。
3. 同时输出“问题类型”和“处理结论”。
4. 先向用户展示所有 Bug 的修改、确认、人工和阻塞分组。
5. 收集用户已经准备好的当前仓库目录，并在用户明确授权后直接修改和复核。
6. 将信息不足或风险较高的 Bug 连同原因和待确认问题交给人工。

## 2. 0.11.0 交付范围

### 包含

- 支持离线 JSON 样例数据，确保没有真实禅道账号也能开发和测试。
- 提供可配置的禅道 REST 数据源，不把禅道版本、URL、认证头和返回字段写死。
- 支持列表分页、超时重试，以及按 Bug ID 并发补拉完整详情。
- 为禅道开源版 21.6 提供个人“指派给我”列表与 REST API v1 详情适配器，默认不枚举产品或读取其他人的 Bug。
- 提供只读接入自检，提前发现令牌环境变量和仓库路径问题。
- 提供 `npx one-click-repair@latest setup` 一键安装器：将 Plugin 复制到稳定的
  Codex 用户目录、注册 Marketplace、生成用户配置、将密码保存到 macOS 钥匙串，并
  在 Token 失效时自动登录续期；源码开发保留 `npm run bootstrap`。
- 提供本地 STDIO MCP Server，将禅道认证状态、Bug 拉取、Bug 详情和代码仓库
  映射暴露为结构化工具。
- 将 MCP Server 及运行依赖打包为 Plugin 内单文件，安装后无需单独启动服务。
- 执行器可从 Codex 用户目录自动发现配置，不依赖克隆仓库作为当前工作目录。
- 支持从 Bug 评论、描述和复现步骤中的多种仓库字段识别代码项目，并允许聊天补充。
- Bug 类型分类：
  - `STYLE`
  - `COPY`
  - `FORM_VALIDATION`
  - `NULL_GUARD`
  - `API_MAPPING`
  - `STATE_LOGIC`
  - `BUILD`
  - `COMPATIBILITY`
  - `PERFORMANCE`
  - `UNKNOWN`
- 处理结论：
  - `AUTO_FIX`
  - `NEED_CONFIRM`
  - `HUMAN_REQUIRED`
  - `BLOCKED`
- 为 `AUTO_FIX` Bug 生成结构化任务包和 Markdown 汇总。
- 在用户看到预览并明确授权前不修改代码；授权采用自然语言，不限制固定口令。
- 直接使用用户提供的当前仓库目录，不创建分支或 worktree。
- 修改后只做代码逻辑复核，不调用项目 script。
- 提供 Codex Skill，规定自动修复的执行步骤和安全门禁。
- 报告采用 `schemaVersion: 2`，私有目录和文件权限分别为 `0700`、`0600`，并以
  同目录临时文件加 `rename` 的方式原子覆盖；完整刷新后清理已不在清单中的旧 Bug 明细。
- 单 Bug 查询优先使用本地报告，缓存缺失或显式刷新时只请求该 Bug，不扫描产品列表。
- 禅道 21.6 默认直接读取“指派给我”的个人列表，只为候选 Bug 补拉详情；全产品扫描仅
  作为显式 `product-scan` 兼容模式，不进行静默降级。
- 报告保存列表模式、候选数、详情请求数、重试数及认证/列表/详情/总耗时，MCP 拉取时
  发送阶段日志，避免长时间无反馈。
- 批量拉取允许产品 Bug 列表或单项详情部分失败，失败范围和脱敏错误写入
  `fetchSummary`、`sourceErrors` 与对应 Bug 的 `fetchStatus`。
- Codex 逐条语义分析后，通过 `bug_record_analyses` 每批最多持久化 50 条分析；用户聊天
  补充优先于 AI 分析，AI 分析优先于关键词预分诊。
- Skill 使用分页 `summary` 返回控制上下文，完整描述、步骤、评论和附件元数据从本地报告
  按 Bug ID 读取。
- 仅按需读取报告中声明的同源 PNG、JPEG、WebP 或 GIF 图片附件，默认限制 5 MiB，
  不落盘、不缓存、不在结构化结果中返回 base64。

### 不包含

- 自动合并主分支。
- 自动关闭或修改禅道 Bug 状态。
- 自动部署到生产环境。
- 自动处理需要产品决策、设计确认、权限安全判断或跨前后端的大范围改造。
- 在未通过验证时将 Bug 标记为已修复。

## 3. 架构

```text
禅道 REST / 离线 Fixture
          │
          ▼
   本地 MCP Server
          │
          ├── 认证与 Token 自动刷新
          ├── 数据源适配器
          └── 代码仓库名称映射与聊天补充
                    │
                    ▼
       Bug 归一化
          │
          ├── 仓库映射
          ├── 映射变化后基于现有报告本地刷新
          └── 分类与风险规则
                  │
                  ▼
        结构化工具结果 + 本地报告
                  │
          ┌───────┴────────┐
          ▼                ▼
     AUTO_FIX          人工处理队列
          │
          ▼
   用户确认 + 当前仓库目录
          │
          ▼
   Codex Skill 定位与修改代码
          │
          ▼
    代码逻辑复核报告
```

## 4. 修改授权边界

- 修改前必须展示预览并获得用户明确授权，但不要求固定口令。
- 用户可以在聊天中补充或纠正仓库、类型和确认答案；本地刷新报告，不要求回写禅道。
- 用户已看过预览时，针对具体 Bug 确认修改或直接给出具体修改方案都视为授权；
  `NEED_CONFIRM`、`HUMAN_REQUIRED` 随即解锁，不重复确认。
- `BLOCKED` 表示仓库或环境客观不可用，不能通过授权绕过。
- 目标目录由用户提供，可直接是用户已经准备好的 worktree。
- 整个流程不执行 Git 命令，不创建或切换分支、worktree。
- 不执行项目 lint、test、typecheck、build 或自定义 script。
- 只通过重新阅读改动和调用链进行代码逻辑复核。
- 涉及鉴权、安全、依赖大版本升级、公共基础组件、后端契约不明确时转人工。
- 信息缺失时不猜测业务预期，输出明确的待确认问题。
- 第一版只生成本地变更和报告，不推送、不建 PR、不回写禅道。

## 5. 配置

配置文件负责提供：

- 当前禅道用户名的本地存储路径。
- 数据源类型和认证环境变量名。
- 禅道返回字段到统一 Bug 字段的映射。
- Bug 中识别或用户补充的代码仓库名称到当前本地仓库目录的映射。
- 自动修复允许类型和最大风险等级。

密码只保存在 macOS 钥匙串中；令牌只从环境变量或 Git 忽略文件读取，不写入配置或日志。

## 6. 分阶段实现

### 0.8.0：安全与可靠性

- 安全原子写入 JSON、Markdown 和 workspace 元数据，读取旧报告时自动兼容 Schema 1。
- 增加报告优先的单 Bug 查询与 ZenTao v1、Fixture、通用 REST 三类直查能力。
- 批量抓取支持部分成功，错误只保留状态、类型和脱敏说明，并采用指数退避与
  `Retry-After`。

### 0.9.0：AI 状态与上下文

- 增加批量语义分析持久化与明确的用户补充优先级。
- 增加 `summary` 分页模式，按需从本地报告读取详情，避免重复请求和大段上下文。
- 增加受约束的图片附件读取，校验来源、重定向、类型、扩展名、内容魔数和大小。

以下阶段保留为后续演进参考：

### 阶段 A：离线 MVP

- 建立配置 Schema 和样例。
- 实现 Fixture 数据源。
- 实现归一化、仓库映射、分类和报告。
- 实现自然语言修改授权、聊天补充、当前仓库选择和验证执行器。
- 建立单元测试与端到端离线测试。

### 阶段 B：真实禅道只读接入

- 根据实际禅道版本确认认证方式、列表接口和字段结构。
- 配置真实接口，不提交令牌。
- 拉取少量 Bug 进行只读试跑。
- 人工检查分类准确率并调整规则。

### 阶段 C：自动修复试运行

- 只选择低风险 Bug。
- 用户准备当前仓库目录并确认修改，由 Codex 执行修复。
- 复核输入、条件、状态变化和 UI 输出的代码逻辑。
- 人工检查 Diff，不自动推送或合并。

### 阶段 D：可选自动化

- 经确认后增加推送分支和创建 PR。
- 经确认后增加禅道评论或状态回写。
- 增加定时执行和通知。

## 7. 0.10.0 验收标准

- 离线命令能够一次处理多个项目的 Bug。
- 每个 Bug 都有类型、处理结论、置信度、理由和下一步。
- 无仓库映射、信息缺失和高风险问题不会进入自动修复队列。
- 用户提供仓库路径后只在本地刷新现有报告，不重新请求禅道。
- `AUTO_FIX` Bug 在未确认前不会修改，确认后使用用户当前仓库目录。
- 代码逻辑复核范围和未做运行时验证的风险能被准确记录。
- 测试不需要真实禅道账号即可运行。
- Skill 目录通过官方 `quick_validate.py` 校验。
- Plugin 目录通过官方 `validate_plugin.py` 校验。
- MCP 初始化、工具列表和 Fixture 工具调用通过自动化测试。
- 单 Bug 直查不请求产品列表；关闭、改派或缺少指派人的 Bug 不进入修改阶段。
- 一个详情请求或一个产品 Bug 列表失败不影响其他可用 Bug，失败项保持阻塞且错误脱敏。
- `summary` 分页不包含完整描述，后续页和本地详情查询不重复访问禅道。
- AI 分析可在重启后读取，但不能绕过客观阻塞、高风险建议或用户修改授权。
- 图片附件的正常读取与类型、大小、同源、重定向和 Token 刷新限制均有自动化覆盖。

## 8. 真实接入前需要用户提供

- 禅道版本、部署地址和可用 API 认证方式。
- 当前用户在禅道中的账号标识。
- 每个代码仓库首次对应的当前本地仓库路径。
- 是否允许后续自动推送分支、创建 PR 或回写禅道。
