# 禅道前端 Bug 自动分诊与修复：第一版实现计划

## 1. 目标

建立一条可重复执行的本地流水线：

1. 一次拉取禅道中指派给当前用户、尚未关闭的 Bug。
2. 将不同产品、项目和模块的 Bug 归一化。
3. 同时输出“问题类型”和“处理结论”。
4. 先向用户展示所有 Bug 的修改、确认、人工和阻塞分组。
5. 收集用户已经准备好的当前仓库目录，并在用户回复“确认修改”后直接修改和验证。
6. 将信息不足或风险较高的 Bug 连同原因和待确认问题交给人工。

## 2. 第一版交付范围

### 包含

- 支持离线 JSON 样例数据，确保没有真实禅道账号也能开发和测试。
- 提供可配置的禅道 REST 数据源，不把禅道版本、URL、认证头和返回字段写死。
- 支持列表分页、超时重试，以及按 Bug ID 并发补拉完整详情。
- 为禅道开源版 21.6 提供 REST API v1 专用适配器，自动枚举有权限的产品并筛选指派给当前用户的 Bug。
- 提供只读接入自检，提前发现令牌环境变量和仓库路径问题。
- 提供一次性 `npm run setup` 初始化：账号写入本地忽略文件，密码保存到 macOS
  钥匙串，Token 失效时自动登录续期。
- 提供统一 `npm start` 入口：直接复用 Token，遇到 `401` 时自动续期并重试一次。
- 支持按 Bug 所属执行 ID 持久化当前本地仓库目录。
- Bug 类型分类：
  - `STYLE`
  - `COPY`
  - `FORM_VALIDATION`
  - `NULL_GUARD`
  - `API_MAPPING`
  - `STATE_LOGIC`
  - `BUILD`
  - `COMPATIBILITY`
  - `PERFORMANCE`
  - `UNKNOWN`
- 处理结论：
  - `AUTO_FIX`
  - `NEED_CONFIRM`
  - `HUMAN_REQUIRED`
  - `BLOCKED`
- 为 `AUTO_FIX` Bug 生成结构化任务包和 Markdown 汇总。
- 在用户明确回复“确认修改”前只预览，不修改任何代码。
- 直接使用用户提供的当前仓库目录，不创建分支或 worktree。
- 修改后只做代码逻辑复核，不调用项目 script。
- 提供 Codex Skill，规定自动修复的执行步骤和安全门禁。

### 不包含

- 自动合并主分支。
- 自动关闭或修改禅道 Bug 状态。
- 自动部署到生产环境。
- 自动处理需要产品决策、设计确认、权限安全判断或跨前后端的大范围改造。
- 在未通过验证时将 Bug 标记为已修复。

## 3. 架构

```text
禅道 REST / 离线 Fixture
          │
          ▼
      数据源适配器
          │
          ▼
       Bug 归一化
          │
          ├── 仓库映射
          └── 分类与风险规则
                  │
                  ▼
        JSON 任务包 + Markdown 报告
                  │
          ┌───────┴────────┐
          ▼                ▼
     AUTO_FIX          人工处理队列
          │
          ▼
   用户确认 + 当前仓库目录
          │
          ▼
   Codex 定位与修改代码
          │
          ▼
    代码逻辑复核报告
```

## 4. 安全门禁

- 修改前必须展示最终清单，并等待用户明确回复“确认修改”。
- 目标目录由用户提供，可直接是用户已经准备好的 worktree。
- 整个流程不执行 Git 命令，不创建或切换分支、worktree。
- 不执行项目 lint、test、typecheck、build 或自定义 script。
- 只通过重新阅读改动和调用链进行代码逻辑复核。
- 涉及鉴权、安全、依赖大版本升级、公共基础组件、后端契约不明确时转人工。
- 信息缺失时不猜测业务预期，输出明确的待确认问题。
- 第一版只生成本地变更和报告，不推送、不建 PR、不回写禅道。

## 5. 配置

配置文件负责提供：

- 当前禅道用户名的本地存储路径。
- 数据源类型和认证环境变量名。
- 禅道返回字段到统一 Bug 字段的映射。
- 所属执行 ID 到当前本地仓库目录的映射。
- 自动修复允许类型和最大风险等级。

密码只保存在 macOS 钥匙串中；令牌只从环境变量或 Git 忽略文件读取，不写入配置或日志。

## 6. 分阶段实现

### 阶段 A：离线 MVP

- 建立配置 Schema 和样例。
- 实现 Fixture 数据源。
- 实现归一化、仓库映射、分类和报告。
- 实现用户确认门禁、当前仓库选择和验证执行器。
- 建立单元测试与端到端离线测试。

### 阶段 B：真实禅道只读接入

- 根据实际禅道版本确认认证方式、列表接口和字段结构。
- 配置真实接口，不提交令牌。
- 拉取少量 Bug 进行只读试跑。
- 人工检查分类准确率并调整规则。

### 阶段 C：自动修复试运行

- 只选择低风险 Bug。
- 用户准备当前仓库目录并确认修改，由 Codex 执行修复。
- 复核输入、条件、状态变化和 UI 输出的代码逻辑。
- 人工检查 Diff，不自动推送或合并。

### 阶段 D：可选自动化

- 经确认后增加推送分支和创建 PR。
- 经确认后增加禅道评论或状态回写。
- 增加定时执行和通知。

## 7. 第一版验收标准

- 离线命令能够一次处理多个项目的 Bug。
- 每个 Bug 都有类型、处理结论、置信度、理由和下一步。
- 无仓库映射、信息缺失和高风险问题不会进入自动修复队列。
- `AUTO_FIX` Bug 在未确认前不会修改，确认后使用用户当前仓库目录。
- 代码逻辑复核范围和未做运行时验证的风险能被准确记录。
- 测试不需要真实禅道账号即可运行。
- Skill 目录通过官方 `quick_validate.py` 校验。

## 8. 真实接入前需要用户提供

- 禅道版本、部署地址和可用 API 认证方式。
- 当前用户在禅道中的账号标识。
- 每个禅道所属执行首次对应的当前本地仓库路径。
- 是否允许后续自动推送分支、创建 PR 或回写禅道。
